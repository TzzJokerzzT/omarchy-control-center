# Omarchy Control Center — MVP (Etapas 1–4)

Feature: Rust TUI inventory + controlled lifecycle operations for software installed
on Omarchy/Arch. Spec source of truth: `../omarchy-control-center-prompt.md` (39,840 B, read in full).

## Specs

- **S1** Project builds and starts on Arch without root: "La aplicación compila sin errores." / "Se inicia en Omarchy/Arch Linux sin requerir root." / "No ejecutes la aplicación completa como `root`." / §9.9 "No se ejecuta toda la TUI como root."
- **S2** Missing tools degrade, never break: "No falla globalmente si falta alguna herramienta." / "La ausencia de una herramienta debe mostrarse como una integración no disponible, no como un error fatal." / §2.9 "Un fallo en un adaptador no debe impedir que los demás funcionen."
- **S3** Inventory of the three initial ecosystems: "Lista paquetes instalados de Pacman, AUR y Flatpak cuando sus herramientas están disponibles." Methods: `pacman -Q`, `pacman -Qi`, `pacman -Qm`, `pacman -Qdtq`, `yay`/`paru`, `flatpak list`, `flatpak info`.
- **S4** No identity collisions: "No confunde componentes de distintos ecosistemas con el mismo nombre." / "Usa una identidad compuesta por ecosistema/adaptador e identificador nativo." / "Conserva el identificador original para consultar y ejecutar operaciones en la fuente correspondiente."
- **S5** Search, filters, details: "Permite buscar, filtrar y consultar detalles." / "Búsqueda: búsqueda por nombre, descripción, identificador y origen".
- **S6** Nothing destructive on navigation: "No ejecuta operaciones destructivas al iniciar ni al seleccionar un elemento." / "No permitas que `Enter` en una fila ejecute una eliminación." / §9.9 "La aplicación no ejecuta comandos destructivos al iniciar." / "Una confirmación cancelada no ejecuta ninguna operación."
- **S7** Every supported removal shows a comprehensible plan and demands explicit confirmation: "Toda eliminación soportada muestra un plan comprensible y requiere confirmación." / "No uses confirmaciones ambiguas como "¿Continuar?" sin explicar qué ocurrirá." / "Para acciones de alto impacto, exige una segunda confirmación o una frase explícita."
- **S8** Security test suite (§9.9), verbatim requirements: "Los argumentos con espacios, comillas, guiones y caracteres especiales no permiten inyección de comandos." / "Las rutas maliciosas o inesperadas son rechazadas." / "Un código de salida de error nunca se reporta como éxito." / "No se realizan borrados recursivos no autorizados." / "Un cambio en el plan tras la previsualización cancela la ejecución."
- **S9** Never invent data: "No inventes valores ausentes. Muestra "No disponible" cuando la fuente no proporcione un dato." / "Cada elemento debe indicar su fuente, método de detección y nivel de confianza."
- **S10** Keyboard schema: "`↑` / `↓`: moverse por listas. `Tab`: cambiar entre paneles. `/`: abrir búsqueda. `Enter`: abrir detalles. `Esc`: volver o cerrar un diálogo. `D`: solicitar eliminación, si está soportada. `U`: solicitar actualización, si está soportada. `?`: mostrar ayuda. `Q`: salir, sin cancelar abruptamente una operación crítica." + "Los atajos deben mostrarse en pantalla y poder descubrirse desde la vista de ayuda." + "Navegación completa mediante teclado; no depender del mouse."
- **S11** Read-only mode: "Añade un modo de solo lectura. Debe permitir explorar el inventario sin exponer acciones destructivas."
- **S12** Documented adapters and limitations: "Documenta los comandos utilizados. Cada adaptador debe explicar qué comandos ejecuta y con qué finalidad." / "Documenta limitaciones reales. Si un ecosistema no expone información fiable, muestra esa limitación en vez de simular soporte."
- **S13** History: "Registra, como mínimo: Fecha y hora. Adaptador. Componente. Tipo de operación. Resultado. Código de salida, si aplica. Resumen de errores. Confirmación de usuario." / "No guardes secretos ni contenido sensible de archivos de configuración en el historial." / "Restringe permisos de archivos de configuración e historial a su propietario."
- **S14** Mandatory pre-flight for destructive actions (§9.3): identify by adapter + native id, obtain the plan, show what will be removed, show dependents/files when the source allows, mark unknown facts, explicit confirmation, execute only the confirmed operation, present real result.
- **S15** Plan drift cancels: "Si cambia el plan de eliminación entre la previsualización y la ejecución, cancela y solicita una nueva confirmación." / "Si el componente ya no existe o cambió su identidad, cancela la operación."
- **S16** No shell string concatenation, no heuristic deletes: "**Prohibido** construir comandos concatenando texto de usuario y ejecutarlos con `sh -c`, `bash -c` o equivalentes." / "Nunca elimines un directorio solo porque su nombre coincide con un paquete." / "No uses `rm -rf` sobre rutas calculadas o no verificadas."

- **S17** Etapa 5 integrations, inspection before modification: "Implementa los adaptadores adicionales de forma independiente." / "Prioriza inspección antes que modificación." / "La eliminación debe integrarse con el gestor correspondiente o requerir una confirmación y explicación explícitas." (Lazy.nvim) / "No modificar `.zshrc` ni archivos relacionados automáticamente sin mostrar un diff y solicitar autorización." (Zsh) / "No tratar cada línea de configuración como un paquete." (Hyprland) / "Separar detener, deshabilitar y eliminar; son acciones diferentes." (servicios) / "No eliminar archivos compartidos o del sistema mediante heurísticas." (fuentes, temas e iconos)
- **S18** Omarchy shell plugins must be listed, inspectable and uninstallable through Omarchy's own manager: user request L8 "que liste los plugins de omarchy y que peuda ver el detalle y desinstalarlos". Authoritative source `omarchy plugin list --json`; removal delegated to `omarchy plugin remove <id> --yes`, never by deleting a directory ourselves.
- **S19** Nothing simulated: "Si un ecosistema no expone información fiable, muestra esa limitación en vez de simular soporte." A first-party plugin shipped by the `omarchy` package must be reported as not removable by us, and a plugin removal backup left by the manager must be labelled as unmanaged rather than pretending to own it.

## Decisions

- **D1 Identity/ownership.** Pacman is the sole owner of every pacman-managed component (official and foreign). AUR contributes helper detection, metadata enrichment and operation routing for foreign components; it never lists a second component for the same package. Sidebar "AUR" is a view over foreign components, not a separate owner. Flatpak owns `flatpak:<ref>:<scope>`.
- **D2 Concurrency.** `tokio` multi-thread runtime; every external command runs off the UI thread with a timeout; results flow to the UI over `mpsc`. Rendering never awaits a process.
- **D3 Dependencies dropped.** No `rusqlite` (JSONL history), no `directories` (XDG env with fallbacks), no `which` (own 20-line resolver, injectable PATH for tests), no `fuzzy-matcher` (unmaintained since 2020; own scored subsequence matcher), no `shell-words` (no shell, argv only).
- **D4 Privilege.** The TUI never runs privileged and never reads a password. A privileged operation releases the terminal, hands the TTY to `sudo` for exactly the confirmed argv, then re-initializes the UI. Absent TTY or passwordless sudo → the operation is reported as unavailable before anything executes.
- **D5 Removal scope.** Default pacman removal is `pacman -R <pkg>` only. Recursive/`-Rns` is not offered in the MVP: if dependents exist the operation is blocked and the dependents are shown. No orphan batch cleanup.
- **D6 Flatpak (optional by design).** Flatpak is compiled into the binary and auto-detected, never a build or install dependency: the project must be fully usable without flatpak. On hosts where the binary is missing the adapter reports "integration unavailable" and every other adapter keeps working. `flatpak` is absent on the author's machine, so the present path is verified through fixtures only and must never be claimed as verified against a live flatpak.
- **D7 Persistence.** `~/.config/omarchy-control-center/config.toml` (0600) and `~/.local/state/omarchy-control-center/history.jsonl` (0600, append-only).
- **D9 tokio dropped.** With synchronous adapters and a command runner that owns its own deadline and kill path, an async runtime adds nothing. `tokio` is not a dependency; background loading uses `std::thread` plus `std::sync::mpsc`, so the process layer is unit-testable without a runtime. This removes one large dependency from the published crate.
- **D10 Package origin is resolved lazily.** `pacman -Qi` does not report the repository, and calling `pacman -Si` 1207 times to find out is not acceptable. List-time origin is `foreign` (from `pacman -Qm`) or `official` with the repository unknown; the repository is filled in from a single `pacman -Si <pkg>` when the details view is opened. The repository is shown as `No disponible` until then rather than guessed.
- **D8 Confirmation.** High-impact removal requires typing the component's native id; `Enter` on a row only opens details; `Esc` cancels and executes nothing.
